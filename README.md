# CSSE — Construction Set Extender

Самостоятельный расширитель TES Construction Set для Morrowind.
Собирается только **Release / Windows x86**, результат — **CSSE.dll**.
MWSE.dll, updater, LuaJIT, Boost, sol, lpeg, yaml-cpp, NuGet и .NET Framework
для сборки не нужны. Заголовки fmt, toml11 и DirectX 8 включены в исходники.

## Обновление

- **Тёмная тема по умолчанию.** Старое значение auto один раз переводится
  в dark; явно выбранные light и dark сохраняются.
- **Значки внутри DLL:** 28 ресурсов каждой темы, всего 56 PNG. Обновлены
  панели инструментов, типы объектов, окна, галочки и кнопки окна слоёв.
  Внешний каталог значков в Data Files больше не используется.
- **Data Files:** фильтр, множественное выделение, групповые действия
  и изменение порядка перетаскиванием или стрелками.
- В решении и GitHub Actions оставлена одна конфигурация **Release**.

## Окно выбора плагинов

| Действие | Управление |
| --- | --- |
| Найти плагин | Filter или Ctrl+F при фокусе в списке |
| Несколько условий | Слова через пробел; учитываются все условия, регистр не важен |
| Очистить фильтр | Clear или Esc в поле поиска |
| Выделить группу | Ctrl+клик, Shift+клик; рамка мышью с пустого места списка |
| Выделить результаты поиска | Ctrl+A в списке, только видимые строки |
| Отметить / снять отметки | Check / Uncheck для выделенных файлов |
| Переключить отметки | Пробел или двойной клик по выделению |
| Изменить порядок | Перетаскивание группы, ↑/↓ или Alt+↑/↓ |
| Отменить перетаскивание | Esc до отпускания кнопки мыши |
| Сделать файл активным | Штатная Set As Active File, один подходящий плагин |
| Применить порядок | OK |
| Отменить ещё не применённый порядок | Cancel |

Фильтр скрывает строки через группы ListView, сохраняя штатные записи
и галочки. Перед передачей OK редактору все строки снова показываются,
поэтому отмеченные ранее плагины не теряются из-за поиска. Описание,
список мастеров и активный файл обрабатываются штатным редактором.

Порядок оригинального редактора задаётся датами изменения ESM/ESP.
CSSE меняет даты **только при OK**, сохраняя содержимое файлов. Одновременно
обновляются кеш дат и список файлов редактора для текущего открытия.
ESM остаются перед ESP; Morrowind/Tribunal/Bloodmoon закреплены.
Плагин нельзя поставить раньше установленной зависимости из TES3/MAST.
Относительная последовательность перемещаемой группы сохраняется.

До записи проверяются структура списка, исходные даты и доступ к файлам;
создаётся JSON-копия дат в **CSSE\load-order-backups\** рядом с редактором.
При ошибке записи выполняется откат прежних дат. Для отдельного
восстановления закройте редактор и используйте скрипт из runtime-архива:

```powershell
.\Restore-PluginOrder.ps1 -BackupFile '.\CSSE\load-order-backups\ИМЯ_КОПИИ.json'
```

Скрипт проверяет все файлы до записи и отказывается применять устаревшую
копию, если какой-либо плагин с тех пор получил другую дату изменения.
Если сторонняя версия редактора использует нераспознанный формат строк,
изменение порядка блокируется; причина пишется в csse.log.

## Сборка на GitHub

1. Загрузите **содержимое** каталога в корень репозитория, включая
   `.github/workflows/build.yml`. При отправке Git используйте `git add .`.
2. Откройте **Actions → Build CSSE**. Сборка запускается при push,
   pull_request и вручную через Run workflow.
3. Скачайте **Artifacts → CSSE-Release-Win32**.

Workflow на windows-2022 проверяет исходники, тестирует порядок и откат
дат, компилирует Release и проверяет x86 DLL. Проверяются импорты
и **фактическое наличие всех 56 PNG внутри DLL**.

| Результат | Назначение |
| --- | --- |
| CSSE-Release-Win32.zip | DLL, пример настроек, инструкции, скрипт восстановления, лицензии |
| CSSE-Release-Win32-symbols.zip | PDB соответствующей Release DLL |
| *.sha256 | Контрольные суммы архивов |

Публикация GitHub Release автоматически не выполняется.

## Локальная сборка

Нужны Windows, Visual Studio 2022 / Build Tools, MSVC v143, Windows SDK
и **C++ MFC for latest build tools (x86 & x64)**. MFC и CRT статические.
Morrowind и установленный редактор для компиляции не требуются.

```powershell
.\scripts\build.ps1 -Configuration Release
.\scripts\package.ps1 -Configuration Release
```

DLL/PDB: build\Release\. ZIP: dist\Release\. Для полной пересборки добавьте
-Rebuild. Можно открыть **CSSE.sln → Release / x86** или Developer PowerShell:

```powershell
MSBuild .\CSSE.sln /t:Build /p:Configuration=Release /p:Platform=x86 /m /nr:false
```

Для прямой сборки CSSE\CSSE.vcxproj платформа называется Win32.
Для Visual Studio 2019 с C++/MFC:

```powershell
.\scripts\build.ps1 -Configuration Release -PlatformToolset v142
```

Скрипт ищет VS 2022 для v143 и VS 2019 для v142; CI использует VS 2022.
Поддержка v142 сохранена по инструкции исходного архива.

## Установка

Закройте редактор и распакуйте runtime-архив рядом с **TES Construction Set.exe**.
Для автоматической загрузки DLL требуется установленный **MGE XE 0.14.3+**.
MWSE.dll для функций редактора не нужен. Редактор, MGE XE и игровые данные
в этот проект не входят.

Сохраните свой csse.toml. При первом запуске он создаётся автоматически,
рядом пишется csse.log. Пример переименовывайте только при отсутствии
собственного конфига. Включение и тема:

```toml
enabled = true

[color_theme]
mode = "dark"
```

Старую папку Data Files\CSSE\icons можно удалить: она больше не читается.
Тёмной теме по-прежнему нужны нативные Windows 10 1809+; на неподдерживаемой
системе сохраняется предусмотренный исходниками переход к светлой теме.

Тестирование в OpenMW сохраняется. В csse.toml можно указать:

```toml
[openmw]
location = 'D:\Games\OpenMW'
```

Временный профиль: Data Files\CSSE\tmp\openmw. Кнопка оригинального Morrowind
также сохранена; внедрение тестового окружения по --fromCSSE требует отдельно
установленной MWSE с её игровым Lua-модулем CSSE. Эта интеграция не включена.

Сборка ничего не устанавливает в игру по умолчанию. Локальное копирование
DLL/PDB можно настроить в config/CSSE.User.props по включённому примеру.

## Проверки и ресурсы

```powershell
python scripts/verify.py
.\scripts\test-order.ps1
python scripts/verify.py --binary build/Release/CSSE.dll
```

Для дополнительных проверок нужен Python 3.9+. Готовые PNG/SVG и RC включены
в исходники; генерация графики при сборке не выполняется. Для редактирования
значков есть scripts/generate-icons.py, требующий Pillow.

Переносимые тесты алгоритма:

```bash
g++ -std=c++20 -I CSSE -include tests/portable_pch.h CSSE/PluginLoadOrder.cpp tests/plugin_load_order.cpp -o /tmp/csse-order-tests
/tmp/csse-order-tests
```

Изменения и границы проверки: [docs/CHANGELOG.md](docs/CHANGELOG.md).
